# Agile Sprint Reference

## Sprint planning
- Define sprint duration: 1 or 2 weeks.
- Create iteration path in Azure DevOps.
- Prioritize backlog items by business value.
- Estimate work using story points or hours.

## Sprint execution
- Start sprint with committed backlog.
- Update status daily.
- Hold daily standup: progress, blockers, next actions.
- Track burndown chart and remaining work.

## Review and retrospective
- Demonstrate completed work.
- Gather stakeholder feedback.
- Capture improvement actions in retrospective.
- Close sprint and prepare next iteration.

## Work item lifecycle
- States: New, Active, Resolved, Closed.
- Use tasks under user stories or bugs.
- Keep work item updates concise and accurate.

## Key artifacts
- Product backlog
- Sprint backlog
- Team board
- Definition of Done
